# UX and flows

> **Online-first (ADR-023).** Offline/SQLite/PowerSync references in this document are
> superseded: the app requires connectivity and has no local write queue.

Web-first, localized UI (Italian in phase 1), explanations in simple target language by
default. A screen must answer one question and lead to one action. Android is the final
client; iOS and desktop are out of scope (ADR-025).

## 1. Information architecture

5 tabs (bottom navigation on Android, centered column on web):

| Tab                         | Question it answers | Main content                                              |
| --------------------------- | ------------------- | --------------------------------------------------------- |
| **Oggi** (Today)            | What do I do now?   | Today's plan, streak, single CTA                          |
| **Pratica** (Practice)      | I want to practice  | Exercises, review, error bank, micro-loop, **Immersione** |
| **Parla** (Talk)            | I want to speak     | Scenarios, conversation, report                           |
| **Progressi** (Progress)    | Am I improving?     | Radar, CEFR, errors, calendar, badges                     |
| **Impostazioni** (Settings) | How does it work?   | Level, AI budget, notifications, export, privacy          |

Rule: the "Oggi" tab is the home and must work on its own. The others are for learners who
want to go deeper, not mandatory. "Pratica" uses a segmented control: **Esercizi | Immersione**,
so the bottom bar stays at 5 tabs.

## 2. Screens

### 2.1 Onboarding (5 steps, < 7 minutes)

1. **Goal**: work, travel, everyday conversation, comprehension.
2. **Time**: 5 / 10 / 20 / 30 minutes per day; streak mode (daily / flexible).
3. **Self-assessment**: 3 quick questions on listening, speaking, writing.
4. **Assessment**: adaptive test with progress bar and pause option.
5. **Taste (optional, skippable)**: formats (film/series/book), genres, themes, difficulty
   tolerance, subtitles, weekly minutes, region.

Before the assessment, the app asks for terms/privacy and AI-processing consent. Voice consent
is requested contextually at the first microphone use; declining keeps text mode available.

Then: a "Here's where we start" screen with level per skill and 3 priorities.
CTA: "Start the first session" (first win within 5 minutes).

**Language profile.** Target English, native Italian, UI Italian. The screen presents the
fixed English course; the data model already stores `target_lang`, `native_lang`, and
`ui_locale`. A language picker is deliberately deferred (ADR-012).

States: anonymous session first, no email required. First run needs network for anonymous auth.
Email is optional and lets you restore the account after reinstalling or signing in again.

No connection at first run: show a clear "serve una connessione per il primo avvio" message.
Do not pretend to onboard offline; there is no offline mode.

After the first session, offer a lightweight "Collega un'email per non perdere i progressi"
prompt with an email magic link; it is skippable and can be done later from Settings.

### 2.2 Oggi (Today)

```
+----------------------------------+
|  Buongiorno, Marco        [18°]  |
|  Streak: 12 giorni  ########     |
|  Salvato sul server              |
|                                  |
|  +----------------------------+  |
|  | Piano di oggi      18 min  |  |
|  | 1. Ripasso      8 card     |  |
|  | 2. Nuovo: present perfect  |  |
|  | 3. Parla: 3 minuti         |  |
|  |           [ Inizia ]       |  |
|  +----------------------------+  |
|                                  |
|  Perché oggi: 3 frasi ti sono    |
|  sfuggite ieri.                  |
|                                  |
|  [Micro-loop 5 min]              |
+----------------------------------+
```

States: first launch (onboarding), plan completed (summary), server unreachable (banner +
retry), AI budget exhausted (conversation disabled with explanation), streak at risk.

### 2.3 Exercise player

- One question per screen, large text, one input.
- Immediate feedback: correct/incorrect + explanation in simple target language.
- "Why this exercise?" as a discreet link.
- A discreet "segnala un problema" link on feedback and corrections -> `user_feedback`.
- Non-punitive progress bar (no hearts).
- Exit always possible; session resumable.

Input types: choice, text, drag ordering, dictation, recording.

### 2.4 Parla (Talk)

- Scenario grid with level and estimated duration.
- Turn-based chat; "hold to speak" button with waveform.
- Editable transcript before sending.
- Corrections in a separate panel, after the turn (they do not interrupt).
- Each correction has a discreet "utile / non utile" feedback -> `user_feedback`.
- Final report: 3 things done well, 2 focus points, useful phrases, "save for review" CTA.

States: microphone permission denied (explanation + text alternative), no network
(conversation unavailable, offer exercises), STT error (retry or type).

### 2.5 Progressi (Progress)

- Multi-axis radar (7 skills) with confidence bands.
- CEFR estimate with interval and trend.
- Recurring errors: rule, example, count, trend.
- Monthly calendar: valid days, grace, repair.
- Badges and awards with visible criteria.

Rule: no numbers without context. "B1 (0.4-0.9)" is better than "B1".

### 2.6 Impostazioni (Settings)

- Level and goal (editable).
- Explanations: simple target language / native.
- UI language: Italian only in phase 1; the setting is read from `ui_locale`.
- Daily AI budget and model (economy/balanced).
- Notifications: on/off, windows, quiet hours, permission status.
- Media tastes: edit or reset genres/themes/formats/region.
- Account: anonymous or email, link email, sign in to another account, sign out.
- Devices: the registered device and revoke.
- Data: server export, import, delete audio, delete taste/recommendation history, delete everything.
- Privacy: what is sent to AI and when; consent status and revocation.
- About: app version, prompt/content versions, licenses.

### 2.7 Immersione (Watch & Read)

Reached from Pratica -> Immersione. Segmented views: **Per te | In corso | Salvati**.

- **Card**: cover, title, kind (film/series/book), level badge, duration/length, one-line
  spoiler-free "perché", availability, actions.
- **Actions**: Salva, Inizia, Non mi interessa, Troppo difficile / Troppo facile.
- **Detail**: spoiler-free synopsis, level note (estimated known vocabulary), guide
  (before/during/after), 3 concepts, functional phrases, progress.
- **After media**: "Racconta in 60 secondi" (voice) or "Scrivi 80 parole"; save phrases;
  5 comprehension prompts; next step.
- **Feedback sheet**: rating 1-5, difficulty (too easy / ok / too hard), optional reason.

States:

| State                     | Behavior                                                      |
| ------------------------- | ------------------------------------------------------------- |
| No catalog                | "Il catalogo non è ancora disponibile" + retry                |
| No availability in region | Show similar titles; explain why                              |
| No title at level         | Offer one band easier with a note                             |
| All rejected              | Ask for taste feedback; reset exploration                     |
| Server unreachable        | Explain and retry; no cached guides                           |
| Age/content warning       | Require confirmation; hide by default                         |

## 3. Key flows

### 3.1 First session

```
Onboarding -> Self-assessment -> Assessment (12-18 min)
  -> Result: level + 3 priorities
  -> First short session (5 min): 3 reviews + 1 production
  -> Summary + "tomorrow 8 reviews are waiting"
```

### 3.2 Daily session

```
Oggi -> Start -> Review (SRS) -> New input -> Production
  -> Summary -> Update streak/XP -> Schedule next review notification
```

### 3.3 Recurring error

```
Error detected (3 times in 14 days)
  -> banner in Oggi: "You got time prepositions wrong 3 times"
  -> 5-minute micro-drill
  -> afterwards: the rule stays in the error bank until mastery >= 0.75
```

### 3.4 Conversation

```
Parla -> Scenario -> Tutor opener
  -> learner turn (voice/text) -> transcript -> tutor response
  -> post-hoc correction -> next turn
  -> end: report -> save errors -> next action
```

### 3.5 Media recommendation

```
Pratica -> Immersione -> card (level, why, availability)
  -> Accetta -> guide (before/during/after)
  -> watch/read -> "Racconta in 60 secondi" / "Scrivi 80 parole"
  -> correction -> save phrases -> SRS
  -> feedback (too easy/ok/too hard) -> taste update -> next recommendation
```

Rejecting a title asks one optional reason and updates the taste profile. Watching/reading
alone does not extend the production streak; the reflection does.

### 3.6 Sign in again

```
Onboarding or Settings -> Accedi -> enter email -> magic link
  -> server profile, last session, due cards and plan restored
  -> "Riprendi da dove eri" (same session or next item)
```

Anonymous users keep their progress by linking an email in Settings. Signing in with an
existing email account restores that account's server data. Writes require connectivity;
there is no offline cache or conflict sheet.

### 3.7 Test-out and remediation

```
Placement/assessment -> level A1-C1 per skill
  -> known concepts: skip new teaching, keep maintenance reviews
  -> "Troppo facile" -> challenge item at the next band
       -> pass: promote, log level_event
       -> fail: keep level, add a short review
  -> lower-level gap detected (speaking/exercise)
       -> targeted remediation block (3-5 items + 1 production)
       -> keep current level; no demotion
```

## 4. UI guidelines

### 4.1 Layout

- Single column on Android; max-width 720 px and centered content on web for reading.
- Keep chat single-column on both clients; corrections stay in the report/detail panel.
- Tap target ≥ 44 px; minimum spacing 8 px.
- No nested modals; use bottom sheets.

### 4.2 Design tokens

```ts
export const tokens = {
  color: {
    bg: '#0F1115',
    surface: '#171A21',
    surfaceAlt: '#1F2430',
    text: '#F2F4F8',
    textMuted: '#A7AFBF',
    primary: '#5B8CFF',
    success: '#3DDC97',
    warning: '#FFB020',
    danger: '#FF6B6B',
    streak: '#FF8A3D',
    xp: '#B388FF',
  },
  radius: { sm: 8, md: 12, lg: 20, pill: 999 },
  space: [0, 4, 8, 12, 16, 24, 32, 48],
  font: { body: 16, small: 14, h1: 28, h2: 22, h3: 18 },
};
```

Equivalent light theme. Minimum AA contrast 4.5:1 for text.

### 4.3 Typography and copy

- UI: Italian in phase 1, direct and non-paternalistic tone; copy from the locale catalog.
- Didactic explanations: simple target lexis (A2-B1 for English; sentences ≤ 15 words).
- Never shout, never multiple exclamation marks.
- Errors: "Quasi. Qui serve _went_, non _go_: parliamo del passato." not "Sbagliato!".
- Corrections cite the rule simply, without academic metalanguage.

### 4.4 Accessibility

- `accessibilityLabel` on all icon actions.
- Screen reader support for exercises and chat.
- Listening and media: transcripts/captions available; no audio-only content.
- Reduced motion respected (`prefers-reduced-motion`).
- Text resizable up to 200% without loss of function.
- Color is not the only state signal (icons + text).

## 5. Required states

Every data screen must handle:

| State                          | Behavior                                                      |
| ------------------------------ | ------------------------------------------------------------- |
| Loading                        | skeleton, not full-screen spinner                             |
| Empty                          | explanation + action ("No reviews: do a micro-loop")          |
| Server unreachable             | banner + retry; no offline mode                               |
| Error                          | human message + "retry" + code for support                    |
| Permission denied              | explanation + alternative                                     |
| AI budget exhausted            | conversation disabled, deterministic exercises remain         |
| Notification permission denied | explain, offer in-app banner, no repeated prompts             |
| Device revoked                 | sign out, explain, allow re-login                             |
| Anonymous user                 | prompt to link an email so progress can be restored           |

Notification deep links: plan -> Today, due review -> Practice, streak -> Talk, media -> detail.
Scheduling respects the profile timezone and DST; a timezone change re-plans future
notifications.

## 6. Micro-interactions

- Exercise completion: short animated check (≤ 400 ms), with reduced-motion option.
- Streak: animation when the valid day is reached, not on every open.
- XP: counter goes up, no annoying sounds.
- No animation that delays the next action.

## 7. Web and Android

- Web is the primary surface and ships first; Android follows with the same server state.
- No desktop or iOS layouts, shortcuts, or installers are planned (ADR-025).
- Android notifications and microphone permissions are part of the Android release smoke.
- No platform-exclusive features in the first release.

## 8. Usability criteria

- A new learner reaches the first correct answer in < 3 minutes.
- Every screen has one obvious primary action.
- The learner can always understand "why this exercise" and "what happens next".
- The online loop is complete and network loss is reported clearly.
- Time to start a session from a cold app launch is ≤ 10 seconds.

## 9. Internationalization (i18n)

- `ui_locale` comes from the user account; fallback chain `it -> en`; a missing key fails the build.
- Catalogs live in `packages/ui/i18n/<locale>.json`; keys are namespaced (`today.plan.title`).
  Components never contain literal copy.
- ICU messages for plurals and gender; `Intl` for dates, numbers, and relative time.
- Layout uses logical properties (`marginStart`, `paddingEnd`); directional icons are mirrored
  where meaningful. RTL is supported by the layout even if no RTL locale ships now.
- A pseudo-locale (`en-XA`) build runs in development to catch hardcoded strings and overflow.
- Language separation: exercises and tutor turns are in `target_lang`; explanations follow
  `explanation_mode`; UI chrome follows `ui_locale`.
- Tests: key parity between locales, no missing keys, pseudo-locale build, and a screenshot
  per supported locale.

Phase 1 ships `ui_locale=it` only. Adding a locale must be a translation task, not a refactor.
