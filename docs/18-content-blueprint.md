# Content blueprint: themes, combinations and recipes

This is the working map for producing real coverage without inventing every item from scratch.
It turns the beta target in `docs/17-learning-experience.md` into repeatable combinations.

## 1. The eight axes

Every piece of content is a combination of:

1. **Level**: A1, A2, B1, B2, C1.
2. **Skill**: grammar, vocabulary, reading, listening, speaking, writing, pragmatics.
3. **Can-do**: the observable task the learner should perform.
4. **Scenario/theme**: where the language is used.
5. **Language focus**: grammar concept or lexical set.
6. **Item/task type**: cloze, MCQ, reading, listening, roleplay, writing, etc.
7. **Register**: casual, neutral, formal.
8. **Modality**: text, audio, spoken, written.

Do not create a Cartesian product of all eight. Pick a **scenario**, give it 8-10 tasks, and
reuse the same language focus across two or three scenarios. That is how 60 scenarios become
600+ practice tasks.

## 1.1 Life-first rule

Every **core** scenario must pass this test:

- It happens in ordinary life, not only in a classroom or an exam.
- The learner can use it within the next 7 days.
- It has a concrete outcome: order, ask, book, return, explain, arrange, complain, negotiate.
- It connects at least three skills, not just one grammar point.
- It reuses one grammar focus, one lexical set and one pragmatic function.
- It has a transfer task: after the lesson, the learner can do the real thing.

Core/extension mix:

| Level | Core life | Goal extension |
| ----- | --------: | -------------: |
| A1    |      100% |             0% |
| A2    |      100% |             0% |
| B1    |       80% |            20% |
| B2    |       65% |            35% |
| C1    |       50% |            50% |

Goal extensions are work, exam, academic or media packs selected from the learner profile. They
never replace the life spine: a learner who wants work English still needs to book, complain,
explain a problem and make small talk.

## 1.3 Goal tracks

Life is the default spine. Technical and academic content is a **first-class track**, selected
from the learner profile, not an afterthought.

| Track             | Best for                 | Share of practice | Content                                                       |
| ----------------- | ------------------------ | ----------------: | ------------------------------------------------------------- |
| Life              | everyone (default)       |           50-100% | food, home, health, travel, money, city, social, problems     |
| Work / technical  | goal work, professionals |            20-50% | standups, email, support, data, product, security, operations |
| Academic          | exam/academic goal       |            20-50% | lectures, abstracts, seminars, summaries, research Q&A        |
| Media / immersion | comprehension goal       |            20-40% | films, series, articles, reviews, interviews                  |

A1/A2 stay mostly life and simple work/classroom contexts. B1 introduces short technical/academic
tasks. B2/C1 can reach 50% technical/academic when the goal requires it.

Rules:

- Maximum 1-2 new technical terms per item; explain them in simple language.
- No acronyms without expansion; no unexplained jargon in A1/A2.
- Every technical/academic task still has a real transfer: a real email, a real explanation, a
  real summary, a real meeting contribution.
- Keep the life spine: a technical learner still needs small talk, requests, complaints and
  clarification.

## 7. Item/task playbook

| Type           | Recipe                                                                     |
| -------------- | -------------------------------------------------------------------------- |
| Cloze          | One context sentence, one blank, 3-4 options, one answer, one explanation. |
| MCQ            | Short question/passage, 3-4 options, plausible distractors.                |
| Transformation | Source sentence + instruction + expected answer.                           |
| Word order     | Tokens + instruction; one correct order.                                   |
| Dictation      | Short audio + text; exact answer with tolerance rules.                     |
| Listening MCQ  | 30-60s transcript/TTS, 1-3 questions (gist/detail/inference).              |
| Reading MCQ    | 50-150 words, 3 questions (gist/detail/inference).                         |
| Free writing   | Prompt, audience, word range, checklist, rubric.                           |
| Roleplay       | Situation, goal, constraints, target phrases, rubric.                      |
| Shadowing      | Audio + transcript; intelligibility, not accent.                           |
| Reuse lexicon  | Use target words in a new context.                                         |
| Error spotting | One sentence with exactly one error; identify/fix.                         |

## 8. Combination recipes

Each recipe is one scenario producing 8-10 tasks.

1. **A1 café**: order + present simple + food vocab + listening MCQ + roleplay + short writing.
2. **A1 directions**: imperatives + prepositions + city vocab + map reading + speaking.
3. **A2 travel problem**: past simple + transport vocab + message reading + polite request + roleplay.
4. **A2 pharmacy**: symptoms + should + body vocab + listening + roleplay.
5. **B1 standup**: present perfect + work vocab + listening + summary + short writing.
6. **B1 complaint**: polite requests + hedging + service vocab + email + roleplay.
7. **B2 negotiation**: conditionals + hedging + work vocab + listening + speaking.
8. **B2 article**: passive + environment vocab + reading inference + summary + discussion.
9. **C1 meeting**: inversion/hedging + professional vocab + listening + debate + minutes.
10. **C1 academic**: nominalization + academic vocab + lecture + summary + Q&A.

## 9. Quotas and math

Beta practice target: **2,400**.

| Area       | Target |
| ---------- | -----: |
| Grammar    |    700 |
| Vocabulary |    600 |
| Reading    |    350 |
| Listening  |    300 |
| Speaking   |    150 |
| Writing    |    100 |
| Pragmatics |    200 |

Ways to reach it without inventing every item:

- 60 scenarios × 8-10 tasks = 480-600 tasks (spread across reading/listening/speaking/writing/pragmatics).
- 150 concepts × 4 items = 600 grammar/vocabulary items.
- 70 reading texts × 5 questions = 350.
- 60 listening clips × 5 questions = 300.
- 50 speaking tasks × 3 prompts = 150.
- 50 writing tasks × 2 versions = 100.
- 40 pragmatic functions × 5 situations = 200.

Assessment beta: **600** = 120 per level, roughly 17 per skill per level.

Every item/task must carry:

```ts
  id: string;
  level: CefrLevel;
  skill: SkillDomain;
  canDoId: string;
  conceptId: string;
  theme: string;
  scenarioId: string;
  function: string;
  register: 'casual' | 'neutral' | 'formal';
  textType: string;
  itemType: ItemType;
  difficultyB: number;
  prompt: string;
  audioText?: string; // listening only
  options?: Option[];
  answerKey: unknown;
  explanation: string;
  license: 'original';
  reviewStatus: 'draft' | 'pending' | 'approved';
  tags: string[];
};
```

## 11. Quality and dedupe checklist

- CEFR vocabulary and sentence length fit the level.
- Exactly one defensible answer; distractors are plausible but wrong.
- No protected text, real names, brands, politics, religion, stereotypes.
- Listening transcript matches the audio text exactly; no transcript shown before the attempt.
- Speaking has a typed fallback; writing has a rubric and word range.
- Prompt is unique against the whole bank; options are unique.
- Explanation is simple target language, one sentence.
- Human review samples 10% per level/skill.

## 12. Batch workflow

1. Pick **10 scenarios** from one level.
2. For each scenario, write 8-10 tasks across skills using the recipes.
3. Run `validateFoundationItems` + duplicate checks.
4. Seed with `pnpm seed:content`.
5. Run `pnpm content:coverage:target`.
6. Review 10%, then approve.
7. Repeat by level; keep one scenario per theme to avoid repetition.

This is the practical route from 538 items to 2,400 practice + 600 assessment without a
combinatorial explosion.
